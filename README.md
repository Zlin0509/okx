# OKX 自动交易工作台

可本地运行的合约策略研究与自动执行平台。Python / FastAPI + SQLite + 原生 JavaScript，中文控制台，无外部 CDN。默认 `demo` 环境、离线演练数据源，不需要密钥；接入 OKX 后仍默认模拟盘。

## 启动

需要 macOS 或 Linux、Python 3.11+、[uv](https://docs.astral.sh/uv/getting-started/installation/)。

```bash
uv sync --frozen --group dev
cp .env.example .env
chmod 600 .env
uv run uvicorn okx_workbench.app:app --host 127.0.0.1 --port 8000
```

浏览器打开 <http://127.0.0.1:8000>；接口文档 <http://127.0.0.1:8000/docs>。终端 `Ctrl+C` 停止服务。每个数据库只允许运行一个服务进程，请勿使用多个 worker。仅绑定本机；此版本不提供多人身份认证，不应公开到互联网。

操作顺序：选择合约和周期 → 自动生成策略 → 检查后 30% 样本外结果 → 按需调整参数运行全样本回测 → 确认环境后启动 → 查看执行记录。生成与回测不会启动交易。策略启动后每 15 秒检查已完成 K 线，可手动“执行一次信号”。页面启动确认显示保存的参数，修改表单只影响新回测，重新生成才能保存新策略。一次仅启用一个策略。

离线行情是随时间滚动的确定性合成 OHLC，不是真实市场行情；本地订单和收益只计入演练账本。`1H` 信号可能为空仓，未出现开仓信号时不会制造订单。回测与验证可在无密钥情况下完成。

## 连接 OKX 模拟盘

1. 在 OKX **模拟交易**环境创建 API Key，使用独立测试子账户，授予读取和交易权限，无需提币权限。
2. 在服务端 `.env` 填写以下项，保留 `OKX_MODE=demo`：

```dotenv
OKX_MODE=demo
OKX_DATA_SOURCE=okx
OKX_API_KEY=你的模拟盘APIKey
OKX_SECRET_KEY=你的Secret
OKX_PASSPHRASE=你的Passphrase
```

3. 在 OKX 设置单向持仓（`net_mode`），准备 USDT 模拟余额，目标合约使用逐仓模式，建议先设为 1 倍杠杆。软件不会修改账户持仓模式或杠杆。使用无其他机器人/人工交易的独立子账户，保证风险快照与实际执行一致。
4. 重启服务，**重新生成并验证策略**后手动启动；界面显示“OKX 模拟盘”。模拟请求带 `x-simulated-trading: 1`，凭据只在服务端读取，不写入数据库、不返回浏览器。环境变量优先于 `.env`。

支持官方域名 `https://www.okx.com`、`https://us.okx.com`、`https://eea.okx.com`；按注册地区在 `.env` 设置 `OKX_BASE_URL`。不会向自定义域名或重定向目标发送密钥。

支持 BTC-USDT-SWAP、ETH-USDT-SWAP，1H / 4H / 1D，USDT 本位线性永续；目标合约只接管单向逐仓多仓。已有空仓、全仓或双向持仓会被拒绝。请不要让软件接管同合约的人工作业仓位。

## 账户互斥与实盘禁用

**本版禁止实盘启动**。即使配置 `OKX_MODE=live`、完整确认短语和凭据，配置校验也会拒绝。当前没有跨主机协调器和 fencing（阻止旧实例继续下单的机制），不能提供跨主机账户级去重与总限额保证；没有环境变量可绕过。此前模拟账户验证不等于实盘验收。

模拟盘从已认证 `/account/config` 的 UID 建立稳定 scope 和客户端订单号，更换同账户 API Key 不改变去重身份。同一主机、同一 OS 用户使用固定目录 `~/.local/share/okx-workbench/accounts.sqlite3`，以 SQLite 原子绑定一个 UID 到一个规范数据库路径；第二数据库/Key 会被拒绝，原数据库内通过写锁和唯一键串行处理。绑定不随服务退出释放，恢复时继续使用原数据库，不要删除协调记录或订单账本。

这是**单主机、单 OS 用户、同一持久化目录**的模拟盘约束，不是分布式锁。不同主机、OS 用户、容器独立目录或 NFS 场景不能保证互斥；这些部署不支持实盘。独立机器人和人工交易不在本机协调范围，模拟盘仍须使用独立子账户。切换不同 UID 需要独立数据库。

旧版当前 Key 的意图用已认证 Key 指纹确认归属后迁移到 UID。旧 Key 已撤销时，用新 Key 的认证账户逐条查询旧客户端订单号，并核对合约、方向、数量、交易所订单号与本地终态；匹配后终态和未终态均可迁移，保留原 ID、去重、历史审计和迁移证据。迁移前最后一次下单时间之前的信号禁止重放。查无、记录超出交易所保留期、身份/终态不匹配均不能证明归属；未能核实的本地取消/拒绝记录也继续阻断，需恢复原 Key 或取得可核实订单，不能只凭本地 filled 标签放行。

迁移和订单/策略更新在同一数据库事务内回滚；固定协调目录内文件锁串行保护绑定与迁移。普通迁移失败只撤销本次新建绑定，不删除已有绑定。进程崩溃会保留已持久化的账户绑定，以同一数据库重启恢复；不能删除绑定改用空库绕过旧意图。

## 策略和回测口径

- 策略为均线趋势的**做多 / 空仓**模型：快均线大于慢均线时目标为多仓，否则目标为空仓；不叠加仓位，不反手做空。交易量受预算、账户权益和硬限额共同限制。
- 自动生成搜索 9 组均线参数，仅用前 70% 连续 K 线按“收益率减最大回撤”选参，后 30% 独立验证。它是可解释的规则搜索，不是大模型预测或收益承诺。
- 使用最近最多 300 根 K 线，过滤未完成 K 线并验证时间连续。不是长历史研究系统。1D 在 OKX 按交易所默认日线边界；离线按 UTC 生成。
- 回测从上一根收盘获取信号，下一根开盘成交；最后一根收盘强制平仓。计算净收益、权益曲线、最大回撤、交易胜率、交易数和手续费，可导出权益 CSV。
- 全样本、训练和样本外回测共用执行引擎预算函数，应用服务端单笔、总仓位、权益比例和可用余额限额。10,000 USDT、5% 策略预算、默认单笔上限 100 USDT 时，有效初始名义预算为 100 USDT（1%），不再按 500 USDT 回测。
- 回测默认单边滑点成本假设与服务端 `MAX_SLIPPAGE_BPS` 数值一致（默认 20 bps），可更改场景假设。IOC 偏移上限相对实时盘口，不是相对信号收盘价的成本，不能保证实际成本与回测相同；执行延迟未建模。
- 每份结果保存合约、周期、均线、预算、初始资金、手续费、滑点、数据区间和生成时间。输入变动立即标记上次回测；旧收益与 CSV 始终对应保存的快照，重新回测才更新。
- 理论回测含双边手续费和滑点，不含资金费、清算、实际盘口深度；连续数量未按合约张数取整。实际执行受最小张数约束，不能直接用回测收益推断模拟盘或实盘收益。
- 离线账户：初始 10,000 USDT、固定单边 5 bps 费用，显示累计已实现收益减全部手续费及当前未实现盈亏。
- OKX 账户：权益、可用余额与未实现盈亏来自账户接口；“已实现净收益”取最近最多 100 条成交的平仓盈亏 + USDT 手续费/返佣 + 最近最多 100 条资金费账单，窗口不同，**不是账户累计收益或存取款调整后的收益率**。接口保留期和返回记录不足时按实际可见窗口显示。离线、回测、真实账户口径在界面分别标注。

## 风控与订单生命周期

默认 `MAX_ORDER_USDT=100`、`MAX_POSITION_USDT=500`、`MAX_EQUITY_FRACTION=0.10`、`MAX_SLIPPAGE_BPS=20`，均从服务端读取。开仓预算为策略预算、单笔限额、账户全部永续仓位剩余限额和可用余额的最小值。其他永续持仓也占用额度；账户有挂单时暂停下单。退出必须为 `reduceOnly`，允许一次减少超过单笔开仓限额的已有仓位。

合约张数从 OKX `ctVal`、`lotSz`、`minSz` 计算并向下取整，价格按 `tickSz` 取整。使用在实时买一/卖一附近、受价格偏移上限约束的 IOC 限价单，避免无界市价成交。IOC 可能部分成交或取消；提交成功仅标为 `accepted`，后续通过查询订单获取实际状态。实际滑点相对信号价仍受信号到执行的时间差影响。

SQLite 先提交 `reserved` 意图，再独立提交 `submitting` / `submit_started` 标记，最后才允许 POST；网络请求后的崩溃回滚不能抹掉提交开始标记。在线 `clOrdId` 由环境、账户 UID、合约、周期、K 线时间和方向确定，不随策略或 Key 重建改变。唯一键与数据库写锁防止并发重复提交。

- 请求超时、断网或响应不完整 → `unknown`，暂停策略，**不自动重发**。
- 服务启动先暂停并逐笔对账，单笔失败不遮住其他订单。“订单对账”同样先暂停，未结束和未知订单持续显示在总览阻断区。撤单检查每笔返回码。
- 新版确定未提交的 `reserved`、离线未完成事务可安全转为 `canceled_local` 并保留去重；旧版意图或已有提交标记的订单必须按不确定结果查单。
- **未知或已提交订单禁止人工作废**，不提供解除表单；旧客户端 `/abandon` 请求一律 409 并暂停。连续查无次数、冷却时间、空账户快照都不能证明不会迟到成交。保持阻断、持续只读查单，直到交易所确认 filled / canceled / mmp_canceled；新版本也会把旧版 abandoned 恢复为 unknown，保留原审计后重新对账。
- 服务运行时即使策略暂停，也每 15 秒对已验证账户的未结束订单只读对账；发现迟到成交会更新成交量与审计，**不会自动恢复策略、重发或平仓**。归属验证失败需人工重试对账；服务停机期间不对账，重启继续查询。空 data 和 51603 均保持 unknown，错误码保留。永远无法确认终态的订单可能持续阻断。
- 重启后全部策略暂停；同账户换 Key 保留 UID 去重，不同账户或数据源需重新生成策略。
- “暂停全部策略”停止后续下单，可能等待当前已开始的请求结束；**不会自动平仓或撤销已有订单**。未知订单按上述流程处理，仓位应在 OKX 人工管理。
- 暂停递增数据库控制版本，原子作废此前未完成的启动。HTTP 启动需携带 `/api/state` 的最新 `control_epoch`，过期请求返回 409；前端忽略已作废响应，不追加 tick。
- 所有周期仅在收盘后 `MAX_SIGNAL_AGE_SECONDS` 内执行（默认/最大 300 秒）。从原已确认 K 线固定 close_ts_ms 和 deadline_ms，在预检后、提交标记前和实际 POST 紧前再次校验，绝不重置有效期；过期或超前信号返回年龄和等待提示，不补单；持续运行的策略等待下一根有效信号，手动执行同样受限。
- 断连后持续显示待同步及最后同步时间，金额清空，启动/手动执行禁用。暂停 POST 确认与后续刷新失败分别反馈。
- `data/` 包含持仓账本、意图和审计记录，应持久化和备份。不要删除数据库或运行多个数据库实例连接同一账户；新数据库不能替代旧意图记录。`.env` 和 `data/` 均被 Git 忽略。

本机接口有 Host 校验、同源检查、JSON 写请求和 CSP，防止网页跨站调用。它不是多人访问控制系统。首版没有交易所端止损、日亏损熔断、WebSocket 推送、长历史分页研究和完整资金流水归因。

## 验证与开发

```bash
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
node --check okx_workbench/static/app.js
```

测试采用 HTTP Mock 与临时数据库，无需密钥，不发送真实订单。GitHub Actions 使用 Python 3.11 / 3.14。详细验证记录见 `docs/VALIDATION.md`。

主要接口：`GET /api/state`、`GET /api/market`、`GET /api/account`、`POST /api/strategies/generate`、`POST /api/backtests`、`GET /api/backtests/{id}/export.csv`、`POST /api/strategies/{id}/start`、`POST /api/strategies/{id}/tick`、`POST /api/orders/reconcile`、`POST /api/orders/{id}/cancel`、`POST /api/stop`。写请求均需 `Content-Type: application/json`；启动体示例 `{"confirmation":"START_OFFLINE","control_epoch":12}`，版本从最新 `/api/state` 读取；模拟盘确认用 `START_DEMO`。另有 `GET /api/strategies/{id}/signal`、`GET /api/orders/{id}/audit` 提供信号预览和审计查询；旧的 `POST /api/orders/{id}/abandon` 仅保留为拒绝接口。

实现依据：[OKX V5 官方接口文档](https://www.okx.com/docs-v5/en/)（签名、模拟盘、合约单位、订单状态与账户接口；2026-11-13 核对）。

## 一次性模拟联调脚本

`scripts/demo_smoke.py` 只使用模拟盘，不读取 `.env`，凭据从当前用户独占权限的 JSON 文件在进程内读取（字段 `api_key`、`secret_key`、`passphrase`），不复制文件、不输出凭据。默认仅预检；只有明确授权后传 `--execute-demo` 才会交易。

**先停止主应用**，脚本与主应用共享数据库进程锁与 UID 绑定。默认数据库已统一为 `data/workbench.sqlite3`，也接受进程环境变量 `DATABASE_PATH`；脚本不加载 `.env`，若主应用在 `.env` 配置其他路径，下述两个脚本命令均须显式传主应用账本的 `--database` 绝对路径。即使仅预检也会绑定账本，不可再用 `data/demo-smoke.sqlite3` 作为新默认。此前已绑定旧 smoke 库时，主应用应将 `DATABASE_PATH` 指向该原库继续恢复；不要删除协调记录或复制空库。脚本结束后同路径重启应用，保留全部意图和审计。

```bash
# 仅预检，不下单。将路径替换为自己的受限权限文件。
uv run python scripts/demo_smoke.py --database data/workbench.sqlite3 --credentials-file /secure/path/okx-demo.json
# 在用户明确授权后，一次性测试并清理。脚本不运行后台任务。
uv run python scripts/demo_smoke.py --database data/workbench.sqlite3 --credentials-file /secure/path/okx-demo.json --execute-demo --report data/demo-result.json
```

脚本固定上限 25 USDT，仅在无永续持仓、无挂单、单向持仓、认证和行情预检通过时继续。按真实已完成 K 线选择一组满足快均线大于慢均线的简单规则，经生产 `Engine.execute` 链路触发开仓；查询订单终态与持仓变化，再以 `reduceOnly` 清理本次可归属新增仓位，最终暂停。没有有效期内的做多信号时停止，不补单或伪造行情。报告只有脱敏的信号、合约、数量、成交状态、费用和清理结果。凭据类型/权限不符时停止，不切换实盘。

修复与回归记录见 `docs/REVIEW_FIXES.md`。原始成交记录在 `docs/VALIDATION.md`，本轮修复仅用离线/mock，未重复执行交易。
